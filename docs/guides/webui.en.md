# WebUI: v2 Control Plane

[中文](webui.md) | English · [Documentation](../README.en.md)

The browser and Tauri desktop shell share the management dashboard. It uses the
bot's HTTP service at `HOST:PORT` (port 8080 by default); no extra server port is
required. The legacy `stella-installer/` interface is frozen at `gui-v1-final`.
See [architecture](../architecture/README.en.md) for runtime responsibilities.

## Quick start

1. Start the bot using `python bot.py` or the desktop shell.
2. Open `http://127.0.0.1:8080/`.
3. Complete the first-run setup to create an administrator. Credentials live in
   `<STELLA_HOME>/webui/auth.json`.
4. After login, use overview, chat, platforms, providers, extensions, configuration,
   knowledge, persona, scheduling, groups, data, external agent tasks, and settings.

The configuration form is generated by `deploy/env_schema.py` from the `_env*`
calls in `config/settings.py`. New sections such as `SOCIAL_*` appear as validated
raw fields even without customized explanatory text. Configuration changes require
a bot restart.

Reset administrator credentials with:

```bash
python scripts/webui_reset_auth.py --yes
```

## Features added through 6.1.0

| Page | Browser route | Purpose |
| --- | --- | --- |
| External Agent Tasks | `/#/cometa` | Persistent delegation, progress, artifacts, cancellation, and delivery state |
| Providers | `/#/providers` | Endpoint/role settings and live Codex backend authentication |
| Personal Memory | `/#/data/personal-memory` | Owner/audience inspection, export, and deletion |
| Message Flow | `/#/data/flow` | Versioned topology, recorded transitions, message I/O, historical replay, and completeness diagnostics |
| Knowledge Base | `/#/knowledge-base` | Library, document, retrieval, and grant administration |
| Scheduled Tasks | `/#/cron` | Group schedules, run-now, history, and audit |

Codex authentication is on **Providers → External Agent**, while task management
is on the Cometa page. Authentication changes take effect for new tasks without
restarting; see [Cometa](cometa.en.md).

Message Flow draws recorded execution against the archived topology version.
`running`, interrupted execution, event loss, partial pagination, and unknown
delivery remain distinct. Missing events do not prove that a business action was
skipped or that delivery succeeded. See the [development guide](../development/README.en.md)
for manifest checks and isolated evaluations.

## Frontend development

```bash
cd dashboard
pnpm install
pnpm dev       # Vite :5173; /api proxies to 127.0.0.1:8080
pnpm build     # vue-tsc followed by Vite
pnpm test      # Vitest regression suite
```

Use `WEBUI_SERVE_DIST=false` with Vite. For UI work without a bot, run
`python scripts/dev_webui.py --port 8091`: authentication, configuration, and logs
work, while bot-dependent features such as chat do not.

For a local bundled build, run `pnpm --dir dashboard sync:webui` after
building to synchronize `dashboard/dist` into `webui/dist`. Release CI builds
the dashboard and writes the release version marker before packaging it.

## Authentication and exposure

Protected `/api/v1/*` operations require JWT via Bearer token or HttpOnly cookie;
bootstrap/login/desktop-session endpoints have their own access rules. Login,
setup, and desktop-session are rate limited using
`WEBUI_LOGIN_RATELIMIT_PER_MIN`. Binding `HOST=0.0.0.0` exposes the control plane
to the network: use a trusted network or an HTTPS reverse proxy; doctor reports
the exposure. Write operations are audited in `logs/webui_audit.jsonl`, and API
responses do not return raw keys or tokens.
