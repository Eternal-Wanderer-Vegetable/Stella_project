## 边界设计

三层信息共存，**按消息 id 划分，绝不重叠**：

```
消息 id →  [........会话较早部分........][...尾巴 12 条...]
              ↓ 压缩成一段摘要              ↓ 原文逐条
           「本场对话较早的内容」          「最近的对话」
```

- **尾巴**（C 批已有）：最近 `RECENT_TAIL_LIMIT` 条原文
- **会话摘要**（本批新增）：从 `summarized_up_to_id` 到尾巴起点之间的消息，压缩成一段
- **话题摘要**（整合器产出）：跨会话的长期话题背景

`summarized_up_to_id` 保证摘要覆盖范围严格早于尾巴。8-13 那个 bug 就是两个来源描述同一段对话导致的，这里从数据结构上排除。

**压缩在回复发出之后异步进行**，不阻塞当前回复。摘要从下一轮开始生效——这与 coding agent 的做法一致，且避免一次回复要跑两次 LLM。
