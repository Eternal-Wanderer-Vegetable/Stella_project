C 档：三代键合并迁移（Phase 1 —— 迁移机制 + 配置面收敛，兼容层保留）

## 探索得出的三个关键事实（决定了方案形态）
1. **`deploy upgrade` 不跑 env 合并**——合并只发生在 `deploy migrate` 和 `deploy init --force`（GUI 每次保存都走后者）。因此"删兼容读"不能与迁移同批发布，否则跳过迁移的升级用户静默丢连接配置。
2. **继承链就是运行时兼容机制**：`_env_inherit` 已在运行时实现旧键→新键的值分发，registry 三级解析靠它兜底。本轮保留，删除留给 Phase 2。
3. **GUI 的模型服务卡片和 init 向导今天写的就是旧键**（`LM_STUDIO_BASE_URL/_MODEL`、`CONSOLIDATION_LM_STUDIO_MODEL`，见 init_wizard.py:105-119 与 settings.html managedKeys 注释）——不翻转写入目标，GUI 会持续生产已被隐藏的旧键。

## 迁移映射表（13 键，全部 1:1 值直接沿用，无需 1→N fan-out、无需值换算函数）

| 旧键 | 新键 |
|---|---|
| LM_STUDIO_BASE_URL / _API_KEY / _MODEL | LLM_ENDPOINT_LOCAL_BASE_URL / _API_KEY / _MODEL |
| CONSOLIDATION_LM_STUDIO_BASE_URL / _API_KEY | LLM_ENDPOINT_EXTRA_BASE_URL / _API_KEY |
| CONSOLIDATION_LM_STUDIO_MODEL / _TEMPERATURE | LLM_ROLE_CONSOLIDATION_MODEL / _TEMPERATURE |
| MEMORY_EXTRACT_LM_STUDIO_MODEL / _TEMPERATURE / _MAX_TOKENS | LLM_ROLE_EXTRACT_MODEL / _TEMPERATURE / _MAX_TOKENS |
| ASTRBOT_LLM_MODEL / _TEMPERATURE / _MAX_TOKENS | LLM_ROLE_PLUGIN_MODEL / _TEMPERATURE / _MAX_TOKENS |

语义保持论证（要点）：LM_STUDIO_MODEL 迁到 LOCAL 槽模型，默认拓扑下五个角色全在 LOCAL 槽且继承同一个值，角色显式覆盖（tier 1）不受影响，"本机模型名不发给在线服务商"的槽位守卫（tier 3）不变；`_local_slot_override_warning` 的 `override == master` 比较对迁移后的等值显式设置不误报。

**四个边缘键不迁移、原样保留**：`MEMORY_EXTRACT_LM_STUDIO_BASE_URL/_API_KEY`、`ASTRBOT_LLM_BASE_URL/_API_KEY`——旧体系里它们表达"第五端点"，4 槽体系无法机械映射（EXTRA 已被整合占用）；registry 的偏离告警（registry.py:807-844）继续覆盖，ASTRBOT 两个还喂 provider 元数据默认值。

## 改动清单

1. **deploy/env_keys.py**：`SUPERSEDED` 登记 13 条（旧→新）。不需要 `_VALUE_MIGRATIONS` 条目（值原样沿用走默认路径）。doctor 的 `key → 新键` 提示（checks.py:1044）自动生效。

3. **deploy/init_wizard.py**：`_managed_values` 写入目标翻转——`lm_base_url → LLM_ENDPOINT_LOCAL_BASE_URL`、`chat_model → LLM_ENDPOINT_LOCAL_MODEL`（槽级模型：ROUTER/COMPACT 等本机角色一并生效，等价于旧 LM_STUDIO_MODEL 的分发语义）、`consolidation_model → LLM_ROLE_CONSOLIDATION_MODEL`；validate_answers 注释同步。向导 answers 键名不变，GUI 卡片无需改字段。
4. **.env.example**：三段旧键（:65-69、:79-83、:111-114 及 ASTRBOT_LLM_MODEL/TEMPERATURE/MAX_TOKENS 段）替换为新键等值行；137-266 一带解释继承链的注释重写为指向新键。
5. **config/settings.py**：**不删任何键**。只在旧键段与端点段的注释加"迁移兼容层"说明（SUPERSEDED 已登记、删除待弃用窗口后的 Phase 2）。
6. **deploy/env_schema.py + stella-installer**：`build_schema` 返回值顶层新增 `superseded_keys`（sorted 列表）；GUI `buildAdvancedEnv()` 丢弃 unknown extras 中命中的键——**修复探索发现的 GUI 缓存复活问题**（get_config 缓存的旧键行会在 apply_advanced_env 时写回，迁移永远不彻底）；managedKeys 清单里的三个旧键条目顺手清理。
7. **docs**：configuration.md / configuration.en.md 把 13 个旧键的表格行替换为新键口径，补一段"旧键自动迁移"说明；memory-system / development 里指向旧键的文案顺带改。
