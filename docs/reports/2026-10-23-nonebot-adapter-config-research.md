# NoneBot 适配器配置表单研究（2026-10-23）

## 范围与证据边界

以本地 [适配器目录](../../webui/services/nonebot_adapter_catalog.json) 为清单，逐项核对 `available != false` 的 30 条可选目录记录；OneBot V11 与 V12 共用 `nonebot-adapter-onebot` 发行包。目录另有 Ntchat、Walle-Q 两条 `available: false` 记录，本次不纳入表单。`official` 标记照录本地目录，表示目录当前标记，不等于对包的维护活跃度或实际互通能力作判断。

下表只记录上游文档/配置模型明确写出的字段和连接方式。示例里出现的字段不自动视为必填；没有明确默认值就标成“未说明”。这份调查不证明 Stella 已验证包安装、Driver 组合、真实账号认证或平台收发。上游文档也可能与锁定包版本存在差异，尤其是条目内标明的情况。

## 对前端 schema 的建议（仅基于文档证据）

1. 以适配器为单位提供字段 schema；大多数平台要表达 **Bot 列表/多账号**，不能只用一组固定平铺输入。嵌套对象（如 IMAP/SMTP、intent、OAuth）和条件字段（Webhook、开放平台模式）应按上游 JSON 结构保存。
2. 仅把上游明确标记的字段设为必填、提供明文默认值或自动写入默认值。上表“required 未说明”的字段应保持可编辑并显示“文档未说明是否必填”，不能从示例推导 required。
3. 将连接模式、认证模式作为显式分支：例如 Feishu http/ws、QQ ws/webhook、Milky client/webhook、Bilibili 用户/开放平台、Matrix token/password/OAuth。切换模式时只隐藏不适用的字段，不丢弃已填草稿。
4. 外部协议端、门户凭证、Webhook 公网 URL、Driver 要求属于不同配置面。表单应说明依赖的外部服务/Driver 和回调地址如何配置，但不可把它们误当成 Stella 能自动完成的平台注册或连接验证。
5. 对结构无充分文档的条目（本次为 Heybox；Minecraft RCON 另有冲突文档）保留通用/高级字段入口并链接原文，不制造字段定义。所有字段最终按适配器原始环境变量名和值格式落盘；含密钥项仍需沿用当前敏感值保护规则。

## 需要再次核验的项目

- `nonebot-adapter-ding` 的 schema 以仓库 `master` 配置源码为准；README 没有说明，而配置模型显示两个凭证当前均可空。若锁包版本变动，应重新对照源码。
- Minecraft Wiki 页面日期较旧，Home 的 1.6.0+ V2 说明与“使用”页 RCON 示例冲突。以当前锁定版本 `1.8.2` 的运行源码确认 RCON 是否完全移除，再决定 UI 是否提供该字段。
- Heybox 文档只给配置示例；在可获取正式配置模型/手册前，无法可靠确定字段 required/default、连接模式及 Driver 条件。
- 大部分仓库文档基于 README 示例；若要把 required 和类型作为客户端校验规则，应再针对锁定版本核对各包的 Pydantic 配置模型，尤其是 README 只给示例但未写 required 的适配器。
